# بوابة التحقق الآلي (CI) — تقرير التنفيذ والتحقق

هذا التقرير يوثّق PR الأول من خطة التحسين: توحيد بوابة تحقق تمنع النشر قبل نجاح
`lint` و`typecheck` و`build` و`E2E`، وإزالة المسارات الميتة والسكربتات القديمة.

## 1) ما تغيّر

| الملف | التغيير |
| --- | --- |
| `.github/workflows/ci.yml` (جديد) | سير عمل واحد بدل ثلاثة: `quality` ← `e2e` ← `build` ← `deploy` |
| `.github/workflows/deploy.yml` (محذوف) | كان ينشر بلا أي اختبار |
| `.github/workflows/lesson5-playwright.yml` (محذوف) | كان يشغّل ملف اختبار واحد فقط |
| `playwright.config.ts` | `testMatch` عام + تقرير HTML + تتبّع/لقطة عند الفشل + مهلات مناسبة لعوامل CI |
| `package.json` | `test:e2e`, `test:e2e:report`, `verify` |
| `tests/all-lessons.spec.mjs` (جديد) | مصفوفة تحقق مدفوعة بالبيانات لكل درس منشور |
| `tests/lesson-e2e-helpers.mjs` | دوال مشتركة (`goToLessonStage`, `setRangeInput`, `watchErrors` …) |
| `tests/lesson-1-2…1-4`, `lesson-5`, `lesson-6` | نقل تفاعلات المختبر التي كان يغطيها السكربت المحذوف |
| `scripts/verify-unit-1-lessons.mjs` (محذوف) | لم يعد هناك سكربت تحقق موازٍ يعتمد على قائمة يدوية |
| `scripts/verify-unit-1-pdfs.py` | أصبح يقرأ مخرجات PDF التي ينتجها الاختبار نفسه |
| `README.md`, `docs/*.md` | توثيق البوابة والاختبارات وتحديث الإشارات للسكربت المحذوف |

## 2) لماذا لا توجد قائمة تشغيل يدوية

- `testMatch: "**/*.spec.mjs"` يجعل أي ملف اختبار جديد يُشغَّل تلقائيًا.
- المصفوفة العامة تكتشف الدروس من الموقع نفسه: `/curriculum` ← صفحة الوحدة ← روابط
  الدروس، ثم تصنّف كل صفحة (درس منشور / صفحة انتظار). إضافة درس جديد لا تتطلب
  تعديل أي قائمة.
- عدد المراحل، معرّفات اللوحات، وأسماء المراحل تُقرأ من الصفحة نفسها لا من قائمة ثابتة
  في الاختبار.

## 5) إثبات أن البوابة تكشف الانحدار

1. أُدخل انحدار مقصود في المحتوى: تغيير `figureId` في `lesson-1-1` إلى معرّف غير مسجّل.
2. `npm run build` نجح (الخطأ محتوى لا بناء).
3. `npx playwright test` فشل: `عنصر غير مسجّل في lesson-1-1/taheya` ورمز الخروج 1.
4. بعد استرجاع الملف أُعيد البناء والاختبار فنجحا مجدّدًا.

لأن `build` و`deploy` يعتمدان على `e2e` في `ci.yml` (`needs: e2e`)، فإن فشل الخطوة 3
يمنع بناء المخرجات ونشرها تلقائيًا. ويُرفع `test-results/` و`playwright-report/`
دائمًا (`if: always()`) حتى عند الفشل.

## 6) ملاحظات

- الاختبارات تُشغّل النسخة الثابتة المنشورة نفسها (`npm run build && npm run preview`)
  تحت المسار الفرعي `/Maths_6_Grade/`، فلا تُختبر نسخة مختلفة عن المنشورة.
- `retries: 1` على CI فقط لامتصاص التقلّب العارض؛ العيب الحقيقي يفشل في المحاولتين.
- ملفات PDF الناتجة تُكتب في `test-results/` (مُستثنى من Git) ولا تُضاف إلى المستودع.
